# שיעור 1: מה זה DevOps, מיקרו-סרוויסים והכרת ShopList

## מה לומדות בשיעור

- מה DevOps פותר, ולמה זו דרך עבודה ולא כלי
- מחזור החיים: Plan, Code, Build, Test, Release, Deploy, Operate, Monitor
- מונוליט מול מיקרו-סרוויסים
- ShopList: ארבעה סרוויסים, ולמה כל אחד צריך סביבה משלו

## נקודות לזכור

- **DevOps** היא אחריות משותפת על הקוד, מהרגע שהוא נכתב ועד שהוא רץ אצל המשתמשים.
- שלושה עקרונות:
  - אוטומציה
  - הכול כקוד
  - שחרורים קטנים ותכופים
- **מונוליט:** אפליקציה אחת ותהליך אחד. פשוט להתחיל, אבל באג אחד מפיל הכול.
- **מיקרו-סרוויסים:** שירותים קטנים ונפרדים שמדברים ברשת. כל אחד נפרס בנפרד, אבל יש הרבה חלקים לנהל.
- כל סרוויס צריך סביבה משלו: שפה, גרסה וספריות. **זו הבעיה ש-Docker פותר**, וזה הנושא של השיעור הבא.

## ShopList

```
Browser → frontend (Nginx :80) → backend (Flask :5000) → postgres (PostgreSQL :5432)
                               → stats (Node.js :3000) ───→ backend
```

הדפדפן מדבר רק עם ה-frontend. כל השאר פנימיים. ה-stats כתוב ב-Node.js ומבקש את רשימת המוצרים מה-backend ברשת. אם הוא נופל, רשימת המוצרים ממשיכה לעבוד.

## תרגול

בזוגות, בלי מחשב:

1. **ציור ארכיטקטורה:** לצייר את ShopList עם החיצים, הפורטים והתפקיד של כל סרוויס.
2. **פירוק מונוליט:** חנות אונליין עם משתמשים, מוצרים, הזמנות, תשלומים ומיילים.
   - לאילו סרוויסים לפרק?
   - מי מדבר עם מי?
   - מה קורה אם התשלומים נופלים?
3. **לאן זה שייך?** לכל כרטיס, לקבוע לאיזה שלב בלולאה הוא שייך:
   - גרף מראה שהאתר נהיה איטי מאז הבוקר
   - כתבתי את הקוד של סרוויס ה-stats ועשיתי commit
   - הגרסה החדשה עלתה לשרת
   - החלטנו להוסיף לאתר תיבת סטטיסטיקות
   - בדיקה אוטומטית מצאה שחסרה ספרייה ב-image
   - ה-backend קרס בלילה וקם מחדש לבד
   - יצרתי image מהקוד עם `docker build`
   - סימנו את גרסה 1.2 כמוכנה לעלות לשרת
4. **הכנה לשיעור 2 (על מחשב הכיתה, 10 דק'):**
   - לפתוח את Docker Desktop ולחכות שיעלה.
   - בטרמינל (PowerShell או Git Bash) להריץ `docker run hello-world` ולוודא שמופיעה ההודעה `Hello from Docker!`.
   - לעשות **fork** לריפו של הקורס ב-GitHub, ואז **clone** לעותק שלכן. ההוראות, צעד אחר צעד, ב-[README הראשי](../../README.md#לקבל-את-הקוד-fork-ואז-clone).
   - לבדוק עם `git remote -v` שמופיע שם המשתמש שלכן.
   - להוריד מראש את ה-images של שיעור 2 (לוקח כמה דקות, אפשר בזמן שמסיימות את תרגיל 3):
     `docker pull nginx:1.30-alpine ; docker pull python:3.11-slim ; docker pull node:24-alpine`
